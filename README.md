## 📋 Описание

Этот репозиторий ежедневно обновляет два основных файла:

| Файл | Формат | Назначение |
|------|--------|------------|
| `russia-mobile-whitelist.lst` | Текстовый список доменов | Читаемый формат, удобен для ручной проверки |
| `russia-mobile-whitelist.srs` | Бинарный Rule Set (Protobuf) | ⚡ Максимальная скорость и эффективность для sing-box / Podkop |

### 🔗 Источники данных
- **Основной список**: [`hxehex/russia-mobile-internet-whitelist`](https://github.com/hxehex/russia-mobile-internet-whitelist) — актуальный whitelist для обхода ограничений мобильных операторов РФ.

### ✨ Пользовательские списки (Custom Rules)
Вы можете **постоянно** добавлять или исключать домены из финального правила, не опасаясь, что автоматическое обновление их перезапишет. Для этого в корне репозитория созданы два файла:

- **`custom_deny.lst`** – домены, которые **всегда будут удалены** из финального списка (даже если они есть в источнике).
- **`custom_allow.lst`** – домены, которые **всегда будут добавлены** в финальный список (если их нет в источнике).

Эти файлы обрабатываются **после** загрузки и очистки основного списка, непосредственно перед компиляцией `.srs`. Ваши правки **не теряются** при каждом обновлении.

## 🚀 Подключение в Podkop / sing-box

### Настройки в Podkop:
1. Перейдите в секцию **Внешние списки доменов** (или Rule Sets).
2. Нажмите **«Добавить список»**.
3. Вставьте ссылку на `.srs` файл (см. раздел "Быстрые ссылки" выше).
4. Тип правила: **Domain Suffix** (обычно определяется автоматически).
5. Назначьте правило на нужный outbound (например, `direct` для прямого доступа или `proxy` для обхода, в зависимости от вашей задачи).
6. Сохраните и примените конфигурацию.

> 💡 **Совет**: Всегда используйте `.srs` вместо `.lst`. Он обрабатывается движком sing-box на порядки быстрее и занимает меньше места в памяти роутера.

## ⚙️ Как это работает

### 🔁 Автоматическое обновление
1. **Ежедневно в 03:00 UTC** (или вручную) запускается GitHub Actions.
2. Скрипт скачивает актуальный `whitelist.txt` из репозитория-источника.
3. Очищает список от BOM-символов, пустых строк, пробелов и комментариев.
4. **Применяет пользовательские правила**:
   - Безопасно удаляет домены, указанные в `custom_deny.lst`.
   - Добавляет домены из `custom_allow.lst` (если их еще нет).
5. Компилирует финальный список в `.srs` через официальный Docker-образ `sing-box rule-set compile`.
6. Если есть изменения, фиксирует их коммитом и отправляет уведомление в Telegram.

### 🔄 Триггеры запуска
```yaml
on:
  schedule:
    - cron: '0 3 * * *'          # Ежедневно в 3:00 UTC
  push:
    branches: [main]
    paths:
      - 'custom_allow.lst'       # ➕ При изменении пользовательских списков
      - 'custom_deny.lst'        # ➖ тоже запускает пересборку SRS
  workflow_dispatch:             # Ручной запуск через интерфейс GitHub
```

## 🛠️ Развёртывание своей копии

### 1. Форкните репозиторий
Нажмите **Fork** в правом верхнем углу GitHub.

### 2. Настройте секреты (для Telegram-уведомлений, опционально)
Перейдите в **Settings → Secrets and variables → Actions** и добавьте:
- `TELEGRAM_BOT_TOKEN`: Токен бота от [@BotFather](https://t.me/BotFather)
- `TELEGRAM_CHAT_ID`: ID чата для уведомлений (узнать через [@getidsbot](https://t.me/getidsbot))

### 3. Настройте пользовательские списки (по желанию)
- Создайте или отредактируйте `custom_deny.lst` и `custom_allow.lst` (по одному домену на строку).
- После коммита и пуша этих файлов workflow автоматически пересоберёт `.srs` с вашими правками.

### 4. Запустите первое обновление вручную
1. Перейдите во вкладку **Actions**.
2. Выберите воркфлоу **Update Russia Mobile Whitelist SRS**.
3. Нажмите **Run workflow** → **Run workflow**.

## ❓ FAQ

### Почему файл `.srs` выглядит как "кракозябры"?
Это **абсолютно нормально**. Файлы `.srs` используют бинарный формат Protobuf для максимальной производительности при проверке миллионов запросов. Не пытайтесь читать их в текстовом редакторе — используйте `.lst` для просмотра содержимого.

### Как добавить свои исключения или домены постоянно?
Отредактируйте файлы `custom_deny.lst` (для исключения) или `custom_allow.lst` (для добавления) в корне репозитория. Каждый домен с новой строки. После пуша этих файлов автоматически пересоберётся `.srs` с применёнными правками. При следующих ежедневных обновлениях ваши правки сохранятся.

### Можно ли использовать в других клиентах?
- ✅ **Podkop** — полная нативная поддержка `.srs` и `.lst`.
- ✅ **sing-box** (любая платформа) — нативная поддержка `.srs`.
- ✅ **Clash Meta / Mihomo** — поддержка через `rule-providers` (формат `text` или конвертация).
- ⚠️ **Qv2ray / V2Ray (Xray)** — только текстовый `.lst`, требуется ручная конвертация в правила `geosite` или `domain`.
